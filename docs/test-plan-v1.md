# Test Plan — nextEnglish v1

Generated by /plan-eng-review on 2026-04-30
Owner: louis.nguyen@overdose.digital
Scope: v1 ship target (3 weekends)

## What this plan tests
The shadowing loop end-to-end: ingest → segment → record → score. Highest priority is
the score module (numpy pure functions on audio features) because regressions there
break the product silently without crashing.

## Affected entry points
- `POST /ingest` (URL or file) — `sidecar/server.py`
- `POST /score` — `sidecar/server.py`
- Tauri commands: `ingest_clip`, `start_session`, `save_attempt`, `request_score`
- Frontend: ClipPicker, SegmentList, ShadowSession, ScoreCard

## Key interactions to verify
- Paste URL → segments appear in segment list within target latency
- Drag .mp3 / .m4a / .wav file → segments appear
- Pick segment → original plays
- Tap Record → mic permission prompt → user speaks → tap Stop → score appears
- Score persists; "Try again" replays original and re-arms recording
- Switching segments mid-recording does not orphan an in-flight scoring request

## Edge cases
- 16-min clip ingest → rejected with clear error (per A5A)
- Silent clip ingest → "no speech detected" error
- All-zero recording (silence) → score returns, no crash
- Garbage recording (different language) → low score, no crash
- Browser revokes mic permission mid-recording → graceful UI state, not a white screen
- First-run with no internet → clear "model download required" error
- Sidecar crashes mid-score → Rust restarts it, frontend retries once, then surfaces error

## Critical paths (must work end-to-end)
1. **Golden path:** paste a 30-60s English clip → see segments → record one → see score (E2E)
2. **File drop path:** drop a .wav → see segments → record → score (E2E)
3. **Score ranking:** golden-fixture set proves score function ranks 5+ recordings
   correctly from "good" to "garbage" (unit, the most important test in the suite)
4. **Cap regression:** 16-min input rejected (unit, mandatory after A5A)
5. **Sidecar lifecycle:** app exit → no zombie Python process on Windows (integration)

## What is NOT being tested in v1
- Real YouTube ingest in CI (depends on yt-dlp + network; smoke-test manually)
- Real microphone capture in E2E (Playwright mocks the audio stream)
- Cross-platform packaging (manual: install MSI on a clean Windows VM, click through)
- Pitch overlay UI rendering (manual smoke; component tests are nice-to-have v2)
- demucs vocal-isolation correctness (manual: known-music-backed clip)
